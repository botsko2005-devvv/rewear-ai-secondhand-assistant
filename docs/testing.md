# Тестування системи

## Середовище перевірки
- **Backend:** Swagger UI (`http://127.0.0.1:8000/docs`) та автоматизований скрипт `python backend/test_ai.py`.
- **Mobile + інтеграція:** емулятор Android (`Small Phone API 30`) із запущеним сервером `uvicorn main:app --reload --host 0.0.0.0 --port 8000` та прокиданням порту `adb reverse tcp:8000 tcp:8000`.

## Тестові сценарії Лабораторної роботи 4 (Room Database & Локальна історія)
| № | Сценарій ЛР4 | Вхідні дії та перевірка | Очікуваний результат | Фактично / Статус |
|---|---|---|---|---|
| 1 | Порожня історія | Перехід на вкладку «Історія» при першому запуску (база порожня) | Відображається текст порожнього стану: «Історія порожня. Згенеруйте перше оголошення, щоб зберегти результат.» | Збіг |
| 2 | Два різні запити | Генерація двох успішних оголошень (наприклад, куртка Zara та кросівки Nike) | На вкладці історії з'являється лічильник `(2)` у назві вкладки; записи відображаються у зворотному хронологічному порядку | Збіг |
| 3 | Перегляд деталей | Натискання на картку історії в списку | Відкривається діалог деталей із повними вхідними даними, результатом, датою (`createdAt`) та кнопкою копіювання | Збіг |
| 4 | Фільтрація помилок та low_confidence | Виконання запиту з помилкою (backend недоступний) або з низькою впевненістю (`low_confidence`) | Записи з помилками чи `low_confidence` НЕ зберігаються в базі даних (історія залишається незмінною) | Збіг |
| 5 | Збереження при перезапуску | Закриття застосунку (kill app) та повторний запуск | Раніше збережені успішні генерації успішно завантажуються з Room Database | Збіг |
| 6 | Видалення запису | Натискання «Видалити» в деталях запису та підтвердження в AlertDialog | Запис видаляється з бази даних, лічильник у вкладці зменшується | Збіг |
| 7 | Основний сценарій ЛР2-3 | Перемикання між вкладками «Генератор» та «Історія», генерація нових оголошень, очищення всієї історії з підтвердженням | Плавна навігація через `PrimaryTabRow`, коректне оновлення потоку `StateFlow`, робота діалогу очищення | Збіг |

## Виявлений і виправлений дефект під час тестування
Під час виконання тесту №6 («Неправильний JSON») виявлено, що бібліотека Gson генерує виняток `MalformedJsonException`, який успадковується від `IOException`. Через це блок `catch (e: IOException)` у `ListingViewModel.kt` перехоплював його першим і показував повідомлення про відсутність мережі. Дефект усунуто перенесенням `catch (e: MalformedJsonException)` перед `catch (e: IOException)`.
