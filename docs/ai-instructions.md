# Інструкції для AI-асистента (ReWear AI)

Цей файл містить обов'язкові правила роботи з репозиторієм `rewear-ai-secondhand-assistant` для coding-агентів (Claude Code тощо).

## 1. Контекст проєкту та технологічний стек
- **Mobile (`mobile/`):** Android, Kotlin, Jetpack Compose, Material 3, ViewModel (`mutableStateOf`), Retrofit + Gson + OkHttp (таймаути connect/read по `10 с`). Пакет: `com.rewear.ai`.
- **Backend (`backend/`):** Python 3.10+, FastAPI, Pydantic, Uvicorn (`start.bat`), `python-dotenv`.
- **AI (`backend/ai_provider.py`):** правиловий `MockProvider` (працює без зовнішніх API-ключів).

## 2. Архітектурні межі
- Дотримуйся принципу **тонкий клієнт — розумний backend**: уся класифікація, словники, розрахунок цін і формування тексту виконуються на backend, а не в Android-коді.
- Зберігай зворотну сумісність із маршрутами `GET /health` та `POST /api/v1/listing`. Усі нові поля в JSON-відповідях повинні бути опціональними або мати значення за замовчуванням, щоб не ламати наявні DTO.
- Не додавай Room Database чи екран історії (це задача ЛР4) та не впроваджуй Hilt/Dagger DI (це задача ЛР5), якщо цього прямо не вимагає поточна задача.

## 3. Правила коду та обробки помилок
- **Backend:** усі HTTP-помилки (`422`, `502`, `504` тощо) повинні повертатися у єдиному форматі `{"error": "код", "message": "повідомлення"}` без технічного `stack trace`.
- **Mobile:** усі стани екрана повинні керуватися через `sealed class UiState` (`Idle`, `Loading`, `Success`, `NoResult`, `Error`). У `ListingViewModel.kt` винятки `JsonParseException` та `MalformedJsonException` повинні перехоплюватися **перед** `IOException`.
- Не змінюй `BASE_URL = "http://127.0.0.1:8000/"` у `ApiService.kt` без окремої вказівки.

## 4. Безпека та приватність
- Заборонено зберігати API-ключі, токени або паролі в коді чи комітити файл `.env`. Нові змінні середовища потрібно додавати лише як шаблони у `backend/.env.example`.
- Не додавай нових дозволів у `AndroidManifest.xml` (дозволено лише `android.permission.INTERNET`).
- Не збирай і не передавай персональні дані користувача.

## 5. Порядок роботи агента (Workflow)
1. Перед будь-якими змінами вивчи релевантні файли в `docs/`, `backend/` та `mobile/`.
2. Завжди починай зі структурованого **плану змін** (які файли змінюються, зміни в API/моделях, ризики та план перевірки) і **чекай підтвердження користувача** перед редагуванням коду.
3. Реалізуй зміни малими, ізольованими кроками: спочатку backend, потім mobile.
4. Після кожної зміни наводь точні команди для перевірки (`python test_ai.py`, Swagger UI `/docs`, збірка Gradle `./gradlew assembleDebug`).
