# Вимоги

Статус відносно функціональних вимог з Лабораторної роботи 1.

| № | Вимога | Статус |
|---|--------|--------|
| 1 | Ввід опису, вибір стану, розмір (необов'язково) | Реалізовано. Вибору категорії вручну немає |
| 2 | Клієнтська валідація (не порожньо, не більше 500 символів) | Реалізовано |
| 3 | HTTP API, JSON, помилки 422/502/504 без технічних подробиць | Реалізовано |
| 4 | Backend: валідація, відсікання заборонених слів, категорія, ціна, заголовок/опис, low_confidence | Реалізовано (правила, не LLM) |
| 5 | Стани UI: Idle, Loading, Success, NoResult, Error + повторний запит | Реалізовано |
| 6 | Копіювання оголошення в буфер обміну | Реалізовано |
| 7 | Локальна історія (Room), перегляд, видалення | Реалізовано (ЛР4) |
| 8 | /health, конфігурація через змінні середовища | Реалізовано |

## Нефункціональні вимоги
- Таймаут запиту на клієнті: 10 с (connect і read).
- Персональні дані не збираються і не зберігаються.
- Застосунок не падає при збої мережі, зламаному JSON або помилці AI.
- Android permissions: лише INTERNET.

## Критерії готовності MVP та ЛР4
- Mobile і backend запускаються за README.
- Повний сценарій виконується на емуляторі.
- Локальна історія на базі Room Database зберігає успішні генерації та дозволяє перегляд деталей, копіювання і видалення записів.

## Незавершені функції
- Інтерфейс AiProvider з реальним LLM та DI (ЛР5).
- Аналіз фото.
