# Архітектурні та технічні рішення

## 1. Детермінований `MockProvider` у MVP замість зовнішнього LLM API
- **Рішення:** реалізувати базову AI-логіку на правилах (`MockProvider`) без підключення зовнішнього LLM API.
- **Обґрунтування:** забезпечує стабільну роботу без API-ключів, мережевих затримок і лімітів запитів (час обробки 3–108 мс) та гарантує передбачуваність під час тестування. Інтерфейс `AiProvider` із реальним LLM перенесено на наступний етап.

## 2. Звуження обсягу функцій відносно Лабораторної роботи 1
- **Рішення:** у MVP реалізовано один наскрізний сценарій генерації оголошення; виключено ручний вибір категорії, локальну історію (Room), екран деталей, аналіз фото та DI-фреймворк.
- **Обґрунтування:** дозволяє перевірити повний потік даних `Mobile → Backend → AI → Mobile` із мінімальним ризиком помилок і чітко розділити етапи розвитку проєкту (Room — ЛР4, DI/LLM — ЛР5).

## 3. Підключення емулятора через `adb reverse`
- **Рішення:** використати `BASE_URL = "http://127.0.0.1:8000/"` у поєднанні з командою `adb reverse tcp:8000 tcp:8000` замість адреси `10.0.2.2`.
- **Обґрунтування:** на тестовому емуляторі `Small Phone API 30` була відсутня маршрутизація зовнішньої мережі до `10.0.2.2`, тоді як `adb reverse` надійно прокидає порт напряму через міст ADB.

## 4. Пріоритет перехоплення `MalformedJsonException` у `ListingViewModel`
- **Рішення:** поставити `catch (e: MalformedJsonException)` вище за `catch (e: IOException)`.
- **Обґрунтування:** у Gson `MalformedJsonException` є підкласом `IOException`; правильний порядок блоків гарантує точне повідомлення користувачу при пошкодженій відповіді сервера.
